## A. 类定义体与实例初始化的执行时机

- **日期**：2026-10-29
- **分类**：Python/面向对象
- **类型**：真实错题
- **掌握状态**：已纠正

**原题/情境**

判断下面代码的输出次数与顺序：

```python
print("A")

class Test:
    print("定义类")

    def __init__(self):
        print("创建对象")

t1 = Test()
t2 = Test()
print("C")
```

**用户当时的原始回答**

用户当时回答：类定义体中的 `print("定义类")` 会打印 2 次，`__init__` 中的 `print("创建对象")` 只打印 1 次。

**原有误区**

把“类被调用两次创建实例”误当成“类定义体执行两次”，同时低估了 `__init__` 随实例创建执行的次数。

**正确理解与正确解答**

Python 执行到 `class Test:` 时，会执行一次类定义体并创建类对象；之后每次调用 `Test()`，都会创建新实例并调用一次 `__init__`。因此类定义体执行 1 次，两个实例分别初始化，共执行 `__init__` 2 次。

输出顺序是：

```text
A
定义类
创建对象
创建对象
C
```

也可以概括为 **A B B C**。用户随后已经能够正确回答。

**错误示例**

```text
A
定义类
定义类
创建对象
C
```

**正确示例**

```python
class Test:
    print("类定义体：只在定义类时执行一次")

    def __init__(self):
        print("实例初始化：每次 Test() 执行一次")

Test()
Test()
```

**原因**

类定义体的职责是构造类的命名空间；`__init__` 的职责是初始化每个新实例。两者处于不同执行阶段。

## B. 类定义体中的误缩进与执行时机

- **日期**：2026-10-29
- **分类**：Python/面向对象
- **类型**：助手解释错误；用户主动指出
- **掌握状态**：非用户错误

**原题/情境**

用户一度把下面的数据准备代码缩进在 `class MyMLP` 的定义体内，与 `forward` 方法同层：

```python
class MyMLP(nn.Module):
    def forward(self, x):
        ...

    x = torch.linspace(-2, 2, 21).unsqueeze(1)
    y = x ** 2
    print(x.shape)
```

**用户当时的真实代码/观察**

用户主动指出：这些语句在类定义体内，因此解释器定义 `MyMLP` 时就会执行；并不需要先写 `model = MyMLP()` 才能打印 `x.shape`。

**需要澄清的地方**

上一轮助手错误地建立了“先创建 model，后面才能打印 shape”的因果关系。这不是用户的知识错误，应明确记为助手解释错误。

**正确理解与正确解答**

只要语句位于类定义体中、又不在方法体里，它就在类定义阶段执行一次，并成为类属性或产生当场副作用。实例化不是这些语句执行的前提。

**错误示例**

```python
class MyMLP(nn.Module):
    # 这些训练数据和输出语句会在定义类时执行，不应误缩进在这里
    x = torch.linspace(-2, 2, 21).unsqueeze(1)
    print(x.shape)
```

**正确示例**

```python
class MyMLP(nn.Module):
    def __init__(self):
        super().__init__()

    def forward(self, x):
        return x

# 数据准备应放在类定义之外
x = torch.linspace(-2, 2, 21).unsqueeze(1)
print(x.shape)
model = MyMLP()
```

**原因**

Python 以缩进确定代码块。方法结束后仍与方法定义同层缩进的语句属于类定义体，而不是“等实例化后再执行的主程序”。

## C. torch.linspace 与 unsqueeze 的形状

- **日期**：2026-10-29
- **分类**：PyTorch/张量与模型
- **类型**：真实错题
- **掌握状态**：已纠正

**原题/情境**

判断下面 `x` 与 `y` 的形状：

```python
x = torch.linspace(-2, 2, 21)
x = x.unsqueeze(1)
y = x ** 2
```

**用户当时的原始回答**

用户早期回答 `x.shape` 和 `y.shape` 都是“21”。

**原有误区**

把元素个数 `21` 与张量形状混为一谈，并忽略 `unsqueeze(1)` 新增的维度。

**正确理解与正确解答**

- `torch.linspace(-2, 2, 21)` 生成 21 个标量，形状是 `(21,)`。
- `unsqueeze(1)` 在索引 1 处加入长度为 1 的维度，形状变成 `(21, 1)`。
- 逐元素运算 `y = x ** 2` 不改变形状，因此 `y.shape == (21, 1)`。

```python
x0 = torch.linspace(-2, 2, 21)
assert x0.shape == torch.Size([21])

x = x0.unsqueeze(1)
y = x ** 2
assert x.shape == torch.Size([21, 1])
assert y.shape == torch.Size([21, 1])
```

**错误示例**

```python
# 错误：把 numel 当成 shape
print(x.shape)  # 认为输出 21
```

**正确示例**

```python
print(x.shape)  # torch.Size([21, 1])
print(x.numel())  # 21
```

**原因**

`shape` 描述各维长度，`numel()` 才描述总元素数。二者相关但不是一回事。

## D. nn.Linear 的参数量计算

- **日期**：2026-10-29
- **分类**：PyTorch/张量与模型
- **类型**：真实错题
- **掌握状态**：已纠正

**原题/情境**

计算 `Linear(1, 4) -> ReLU -> Linear(4, 1)` 的可训练标量参数总数。

**用户当时的原始回答**

用户曾把偏置的数量方向写反；之后能够独立算出 `Linear(2, 3) -> ReLU -> Linear(3, 1)` 为 13 个参数，以及 `Linear(1, 16) -> ReLU -> Linear(16, 1)` 为 49 个参数。

**原有误区**

误认为 `nn.Linear(in_features, out_features)` 的偏置数量等于输入维度。实际每个输出单元有一个偏置，所以偏置数量等于 `out_features`。

**正确理解与正确解答**

`nn.Linear(a, b)`：

- 权重形状：`(b, a)`，共 `a * b` 个标量；
- 偏置形状：`(b,)`，共 `b` 个标量；
- 合计：`a * b + b`。

因此：

- `Linear(1, 4)`：权重 4，偏置 4，共 8；
- `Linear(4, 1)`：权重 4，偏置 1，共 5；
- 总计 `8 + 5 = 13`；
- ReLU 没有可训练参数。

**错误示例**

```text
Linear(1, 4) 的偏置是 1 个
Linear(4, 1) 的偏置是 4 个
```

**正确示例**

```python
layer = nn.Linear(1, 4)
print(layer.weight.shape)  # torch.Size([4, 1])
print(layer.bias.shape)    # torch.Size([4])
```

迁移练习：

```text
Linear(2, 3): 2*3 + 3 = 9
Linear(3, 1): 3*1 + 1 = 4
总计 13
```

```text
Linear(1, 16): 1*16 + 16 = 32
Linear(16, 1): 16*1 + 1 = 17
总计 49
```

**原因**

线性层输出向量的每一维都需要自己的偏置。

## E. ReLU 无参数，但参与反向传播

- **日期**：2026-10-29
- **分类**：PyTorch/张量与模型
- **类型**：助手误判澄清
- **掌握状态**：非用户错误

**原题/情境**

讨论为什么执行 `optimizer.step()` 后，下一轮前向传播使用的是已经更新的线性层参数，以及 ReLU 是否参与反向传播。

**用户当时的真实回答**

用户关于“上一轮 `optimizer.step()` 已经更新参数，下一轮 `model(x)` 自然使用新参数”的解释本来正确。助手曾误解用户表述，应记录为助手误判，而不是用户错误。

**正确理解与正确解答**

- ReLU 没有 `weight` 或 `bias`，所以不会出现在 `model.parameters()` 中。
- ReLU 仍是计算图中的运算节点，反向传播时会把梯度乘以局部导数：输入大于 0 时通常传递梯度，输入小于 0 时梯度为 0。
- `optimizer.step()` 更新登记的线性层参数；下一轮前向传播直接读取这些新值。

**错误示例**

```text
ReLU 没有参数，所以它不参与 backward。
```

**正确示例**

```python
h_pre = model.linear1(x)
h = model.relu(h_pre)  # 无参数，但保留在计算图中
y_pred = model.linear2(h)
loss.backward()
```

**原因**

“是否有可训练参数”和“是否参与自动求导”是两个不同问题。运算可以没有参数，但仍然对输入有导数。

## F. 多元素 Tensor 不能直接调用 item

- **日期**：2026-10-29
- **分类**：PyTorch/张量与模型
- **类型**：用户主动发现
- **掌握状态**：已纠正

**原题/情境**

用户主动尝试打印 `model.linear2.weight.item()`，发现运行报错；而 `model.linear2.bias.item()` 可以运行。

**用户当时的真实代码/观察**

- `linear2.weight` 的形状是 `(1, 16)`，含 16 个元素，调用 `.item()` 报错。
- `linear2.bias` 的形状是 `(1,)`，只有 1 个元素，可以调用 `.item()`。

**原有易踩坑**

把 `.item()` 理解成“把任意张量转成 Python 值”。实际上它只适用于恰好含一个元素的张量。

**正确理解与正确解答**

- 标量损失：`loss.item()`；
- 单元素偏置：`model.linear2.bias.item()`；
- 多元素权重：先脱离当前计算图，再展平并转换为列表。

**错误示例**

```python
print(model.linear2.weight.item())  # 16 个元素，运行错误
```

**正确示例**

```python
print(loss.item())
print(model.linear2.bias.item())
print(model.linear2.weight.detach().flatten().tolist())
```

**原因**

Python 单个标量无法无歧义地表示一个包含多个元素的张量；`.tolist()` 会保留全部元素。

## G. model.eval 与 torch.no_grad 的区别

- **日期**：2026-10-29
- **分类**：PyTorch/张量与模型
- **类型**：易混点
- **掌握状态**：待复习

**原题/情境**

评估模型时为什么经常同时写：

```python
model.eval()
with torch.no_grad():
    y_pred = model(x_test)
```

**用户当时的原始注释**

“关闭 dropout 和 batch normalization 等训练时特有的操作。”这个表述方向接近，但不够精确。

**原有易混点**

可能把 `model.eval()` 误解成“关闭梯度”，或把 BatchNorm 在评估模式下的行为说成完全关闭。

**正确理解与正确解答**

- `model.eval()`：切换模块的 `training` 标志。Dropout 在评估时不再随机丢弃；BatchNorm 使用已有的运行统计量，而不是当前批次统计量。它不会自动关闭梯度。
- `torch.no_grad()`：在代码块内不建立自动求导图，减少内存和计算开销。它不会自动把模型切换到评估行为。
- 当前 MLP 只有 Linear 与 ReLU，所以 `eval()` 对数值结果没有实际改变；但规范的评估代码仍可保留两者。

**错误示例**

```python
model.eval()
y_pred = model(x_test)
# 错误解释：eval 已经自动禁止梯度
```

**正确示例**

```python
model.eval()
with torch.no_grad():
    y_pred = model(x_test)
```

**原因**

一个控制“层的运行行为”，另一个控制“是否记录自动求导图”，职责不同。

## H. MSE 不是每个样本误差的上限

- **日期**：2026-10-29
- **分类**：机器学习/实验评估
- **类型**：易混点
- **掌握状态**：已纠正

**原题/情境**

训练结束时 MSE 约为 `0.030828`，是否意味着每个样本的预测误差都小于 `0.030828`？

**原有误区**

把“所有样本的平均平方误差”当成“每个样本绝对误差的最大值”。

**正确理解与正确解答**

对于 `n` 个样本：

```text
MSE = (1/n) * Σ (预测值 - 真实值)²
```

MSE 是平方误差的平均值，不是最大绝对误差，也不是每个样本误差的上限。某些样本误差可以明显大于 MSE，只要整体平均仍较小。

用户的实际例子：`x = 2` 时真实值是 `4`，某次预测约为 `3.5985`，绝对误差约为 `|3.5985 - 4| = 0.4015`，明显大于训练 MSE `0.030828`，这并不矛盾。

**错误示例**

```text
MSE = 0.03，所以每个样本的 |预测-真实| 都不超过 0.03。
```

**正确示例**

```python
squared_errors = (y_pred - y) ** 2
mse = squared_errors.mean()
max_abs_error = (y_pred - y).abs().max()
```

**原因**

平均值只概括总体水平，不能直接约束每个单独样本；而且 MSE 使用的是平方误差，单位与绝对误差也不同。

## I. 插值、外推与受控比较

- **日期**：2026-10-29
- **分类**：机器学习/实验评估
- **类型**：真实错题
- **掌握状态**：待复习

**原题/情境**

训练数据覆盖 `[-2, 2]`。如何区分测试点 `[-1.9, -1.3, -0.7, 0.5, 1.7]` 与 `[2.6, 2.8, 3, 4, 5]`？测试训练范围外的点是否就等同于检查过拟合？

**用户当时的原始回答/实验**

用户曾把“测试训练范围外的点”直接等同于检查过拟合；之后实际测试了两组点：

- 区间内未见点预测约为 `[3.3655, 1.9265, 0.4823, 0.0853, 2.9151]`；
- 区间外点预测约为 `[4.7462, 5.1745, 5.6028, 7.7549, 9.9149]`。

**原有误区**

混淆“分布范围内的泛化”“超出训练范围的外推”与“训练集/独立测试集之间的过拟合判断”。

**正确理解与正确解答**

- **插值**：测试输入落在训练输入范围内部，但具体点没有作为训练样本出现。
- **外推**：测试输入超出训练输入范围。
- **过拟合判断**：比较训练集与独立、同分布验证/测试集的表现；不能只因为测试点在范围外就称为过拟合。
- 当前两组结果来自不同随机初始化、不同训练运行，不能直接构成严格受控的插值/外推对比。

**错误示例**

```text
x=5 在训练范围外，如果预测不好，就说明模型过拟合。
```

**正确示例**

```python
torch.manual_seed(0)
# 训练一次同一个模型
with torch.no_grad():
    y_interp = model(x_interp)
    y_extra = model(x_extra)
# 分别与真实 x**2 比较，保持同一模型和同一训练过程
```

**原因**

ReLU 网络在训练区间外呈分段线性延伸，而目标 `x²` 是二次函数；外推困难是模型结构与数据覆盖共同导致的，不自动等于过拟合。要做公平比较，必须控制随机种子、初始化、训练过程与评估指标。

## J. 欠拟合、过拟合与数据泄漏

- **日期**：2026-10-29
- **分类**：机器学习/实验评估
- **类型**：真实错题
- **掌握状态**：已纠正

**原题/情境**

区分欠拟合、过拟合和数据泄漏，并判断“训练 MSE = 0.001，测试 MSE = 1.5”属于什么问题。

**用户当时的原始回答**

用户原话大意：“欠拟合是训练集表现不理想；过拟合可能是测试集部分混到训练集，像作弊一样导致测试异常优秀。”

**原有误区**

前半句对欠拟合的理解正确；后半句描述的其实是 **data leakage（数据泄漏）**，不是过拟合。

**正确理解与正确解答**

- **欠拟合**：模型连训练数据中的主要规律都没有学好，训练误差高，测试误差通常也高。
- **过拟合**：模型对训练集拟合得过细，训练误差很低，但在独立同分布测试集上误差明显更高。
- **数据泄漏**：测试信息、未来信息、标签信息或由全数据计算出的统计量不当进入训练过程，导致测试结果虚高或评估失真。
- `训练 MSE = 0.001，测试 MSE = 1.5` 是典型的过拟合信号。用户随后已正确回答。

**错误示例**

```text
测试集混进训练集，测试成绩异常好 = 过拟合
```

**正确示例**

```text
训练误差低、独立同分布测试误差高 = 过拟合
测试信息泄露到训练流程、测试指标虚高 = 数据泄漏
训练误差和测试误差都高 = 更像欠拟合
```

**原因**

过拟合是模型泛化能力不足；数据泄漏是实验流程不独立。二者可能同时出现，但概念和诊断方式不同。

## K. k-similar 分组方向

- **日期**：2026-10-29
- **分类**：科研/侧信道
- **类型**：真实错题
- **掌握状态**：已纠正

**原题/情境**

阅读 TCHES 2022《The Hidden Parallelepiped Is Back Again: Power Analysis Attacks on Falcon》第 3.4 节时，判断 `k` 从 4 增大到 10 后，k-similar 分组会变大还是变小。

**用户当时的原始回答**

用户曾把分组方向讲反，认为 `k` 增大后组会合并或变大；之后已纠正。

**原有误区**

没有把“匹配更多前缀位”对应到“条件更严格、组更细”。

**正确理解与正确解答**

k-similar 要求浮点数的：

1. 符号位相同；
2. 指数位相同；
3. 尾数最高 `k` 位相同。

当 `k` 从 4 增到 10，额外要求 6 位相同。一个原有的 `k=4` 组最多按这 6 位的所有组合拆成 `2^6 = 64` 个子组。

结果是：

- 组内输入更相似；
- 单组样本数通常更少；
- 是“拆细”，不是“合并”；
- 论文实验采用 `k=10`。

**错误示例**

```text
k 越大，允许的差异越多，所以组越大。
```

**正确示例**

```text
k 越大，需要一致的最高尾数位越多，条件越严格，原组会拆成更小的子组。
```

**原因**

`k` 是必须匹配的前缀位数量，不是允许不同的位数量。

## L. 噪声均值为零，不会消除不同输入对应的信号偏差

- **日期**：2026-10-29
- **分类**：科研/侧信道
- **类型**：关键知识；非错误
- **掌握状态**：已掌握

**原题/情境**

两条迹线满足：

```text
L1 = 10, N1 = 2
L2 = 14, N2 = -2
T = L + N
```

求 `T1`、`T2`，并解释为什么“噪声平均为 0”并不保证平均结果回到 `10`。

**用户当时的原始回答**

用户正确算出 `T1 = T2 = 12`。这是关键知识点，不应记成用户错误。

**正确理解与正确解答**

```text
T1 = L1 + N1 = 10 + 2 = 12
T2 = L2 + N2 = 14 - 2 = 12
mean(N1, N2) = 0
mean(L1, L2) = 12
mean(T1, T2) = 12
```

噪声均值为 0，只消除了加性噪声的平均偏移；如果两次测量对应不同输入，真实泄漏信号 `L1` 与 `L2` 本身不同，那么平均后得到的是这些真实信号的均值 `12`，不是某一条信号 `10`。

**错误示例**

```text
只要噪声一正一负，平均后的观测就一定等于第一条真实泄漏 10。
```

**正确示例**

```text
平均观测 = 平均真实信号 + 平均噪声 = 12 + 0 = 12。
```

**原因**

random salt 让 Falcon 每次签名的输入发生变化，不能简单地把不同输入的迹线当成“同一信号加独立零均值噪声”。k-similar 分组的目的就是让同组输入更相似，从而减小信号本身的变化。
